# 12 — Kualitas, keamanan, privasi dan operasi

## Identitas dan sesi
Password di-hash dengan Argon2id (dibatasi panjang maks `128` karakter dan **concurrency semaphore maks 4 operasi serentak** = maks `256 MiB` RAM agar kebal serangan OOM login flood); verifikasi gagal menggunakan dummy Argon2id anti-timing enumeration; tidak pernah log plaintext dan **`passwordHash` tidak boleh pernah keluar pada respons API mana pun**. Login manual memakai cookie HttpOnly, Secure (produksi), `SameSite=Lax` (atau `SameSite=None` bila `API_PUBLIC_ORIGIN` memakai subdomain HTTPS terpisah) dengan token sesi yang **disimpan dalam bentuk hash HMAC-SHA256** di database (TTL **7 hari**, maks `MAX_SESSIONS_PER_USER = 10` sesi aktif per akun, fast-fail regex 64-hex sebelum HMAC/MySQL); `SESSION_SECRET`, `COOKIE_SECRET`, `PUBLIC_ORIGIN` non-localhost (serta `API_PUBLIC_ORIGIN` bila diisi), dan S3/RustFS wajib terkonfigurasi kuat (fail-fast di produksi), sedangkan SMTP bersifat opsional saat startup server. Mutasi berbasis cookie dilindungi pengecekan CSRF (`Origin`). Verifikasi kepemilikan email saat registrasi ditunda ke pasca-rilis awal per `K-21`; reset password produksi memakai token 1 jam sekali pakai atomik via SMTP (server tetap menyala bila SMTP belum valid dengan peringatan log startup, dan mengembalikan `503` + log error saat reset password dipanggil ketika SMTP belum siap/bermasalah per `K-13`, membatalkan semua sesi aktif secara atomik saat sandi diubah). Google login tidak ada.

## Proteksi DDoS berlapis (Edge Nginx + Application Layer)
1. **Resolusi IP Anti-Spoofing**: Nginx edge memakai `set_real_ip_from` hanya untuk loopback/RFC1918 (Cloudflare Tunnel / Docker bridge) dengan `real_ip_header CF-Connecting-IP`, menghapus `CF-Connecting-IP` mentah dari klien saat proxy ke API, dan meneruskan `$remote_addr` bersih. Backend `resolveClientIp` memvalidasi format IP via `net.isIP`, menormalisasi `::ffff:` IPv4-mapped IPv6, dan saat `TRUST_PROXY=true` mengambil `CF-Connecting-IP` atau hop non-privat paling kanan pada `X-Forwarded-For` agar kebal pemalsuan header.
2. **Pembatasan Edge Nginx (`infra/nginx/default.conf`)**:
   - Batas koneksi simultan: `limit_conn conn_per_ip 50` (ramah NAT Wi-Fi kampus, menahan connection exhaustion).
   - Rate limit berjenjang (respons 429 JSON terstruktur + `Retry-After`): `auth_limit` (`15r/m`, burst 10) untuk login/daftar/reset, `upload_limit` (`10r/m`, burst 5, **hanya metode POST/PUT** lewat `map $request_method`) untuk unggah avatar/prestasi, `api_limit` (`30r/s`, burst 60) untuk REST API umum, dan `health_limit` (`6r/m`, burst 4) untuk `/health/ready`.
   - `client_max_body_size` ketat per rute (`256k` default/auth, `1m` API JSON, `3m` avatar, `26m` bukti prestasi 3×8 MB + overhead), timeout anti-Slowloris (`client_header_timeout 10s`, `client_body_timeout 15s`, `send_timeout 15s`, `keepalive_timeout 15s`, `reset_timedout_connection on`), kompresi `gzip`, serta `/nginx-health` hanya diizinkan dari loopback/RFC1918.
3. **Hardening Application Layer (`backend/`)**:
   - `InMemoryRateLimiter` bounded LRU (`maxEntries` + sweep 30 detik, anti-OOM Map) dengan header `Retry-After` & `X-RateLimit-*` dan tier khusus per-IP & per-email/per-user (global IP, login, register, forgot-password, upload, join-by-code, ekspor CSV, mutasi, dan `/health/ready`). Catatan `K-14`: rilis awal berjalan 1 instance API.
   - Validasi ukuran & jumlah berkas multipart **sebelum** membaca `arrayBuffer()`, batas `maxLength`/`maxItems` pada skema endpoint, pemotongan `userAgent`/`metadata` audit, `X-Request-Id`, header keamanan terpadu (`security-headers.conf` + `proxy_hide_header` anti-duplikasi), `Cache-Control: no-store` pada API JSON, serta graceful shutdown `SIGTERM`/`SIGINT`.

## Otorisasi
Setiap endpoint memeriksa role, kepemilikan objek, dan `institutionId` di backend. ID dari browser tidak boleh menentukan owner; rute legacy rawan IDOR (`/users/:userId/target`, `?userId=` pada checklist, serta 5 rute legacy `matching`/`invites`) telah dihapus/dinonaktifkan. `/admin/sistem` dan seluruh `/api/v1/system/*` (kecuali read-only `GET /system/point-templates` untuk dropdown aturan poin) dikunci khusus `super_admin` (`K-02`, `K-03`, `K-22`). Uji IDOR wajib lulus untuk profil, avatar, target, tim, pengajuan gabung, checklist, pengajuan prestasi, bukti, audit, dan pengaturan sistem. Super admin tidak boleh men-suspend atau menurunkan peran dirinya sendiri hingga menyisakan nol super admin aktif, dan tidak boleh menaikkan peran akun `mahasiswa` menjadi staf; perubahan peran mencabut sesi aktif target. Semua tindakan sensitif (termasuk override poin validator, ekspor CSV, & pergantian periode) dicatat di audit (di luar transaksi DB agar tidak menahan lock).

## Tata kelola anti-bloat MySQL & RustFS (`K-25`)
- **MySQL**: Pool MariaDB dibatasi (`DB_POOL_LIMIT`, `acquireTimeout: 10s`, `connectTimeout: 5s`, `socketTimeout: 30s`, `idleTimeout: 60s`); 18 indeks komposit/TTL ditambahkan dan 2 indeks redundan dihapus; query dashboard dikolaps dari 22 menjadi 9 `groupBy`; cache baca 30 detik (`BoundedReadCache`, invalidasi eksplisit) melindungi ranking, katalog lomba, dan periode aktif; klik checklist roadmap tidak lagi menulis baris `AuditEvent`; worker/CLI pemeliharaan (`backend/src/lib/maintenance.ts`, `backend/src/scripts/maintenance.ts`) menghapus dalam batch (`LIMIT 500`) sesi kedaluwarsa (`> 7 hari`), token reset (`> 24 jam`), pengajuan/undangan tim terminal (`> 90 hari`), serta `audit_events` sesuai `AUDIT_RETENTION_DAYS` (default `365`; `0` = simpan selamanya sesuai `O-03`).
- **RustFS**: Kuota per pengguna (`USER_STORAGE_QUOTA_MB = 100`), maks revisi (`MAX_REVISIONS_PER_ACHIEVEMENT = 5`), maks pengajuan/periode (`MAX_ACHIEVEMENTS_PER_PERIOD = 30`); penggantian/penghapusan avatar dan pembatalan prestasi oleh pemilik (`menunggu → dibatalkan`) langsung menghapus objek RustFS lama; unduhan bukti & avatar memakai Web `ReadableStream` + `ETag`/`If-None-Match` (`304 Not Modified`) dengan timeout S3 (`5s`/`15s`); retensi bukti tak aktif/ditolak (`STORAGE_RETENTION_INACTIVE_DAYS = 90`, `0` = nonaktif) dan Orphan GC (`> 24 jam` grace window) membersihkan objek yatim tanpa memutus proses unggah aktif.
- **Container & Backup**: Docker Compose membatasi `mem_limit`/`cpus`/`pids_limit`, rotasi log `json-file` (`10m × 5`), dan bind loopback default (`WEB_BIND_HOST:-127.0.0.1`); skrip `backup-db.sh` dan `backup-storage.ts` memakai rotasi `--keep-days` (`BACKUP_RETENTION_DAYS = 14`) dan membersihkan DB uji pasca `--test-restore`.

## Data pribadi dan publikasi
Kumpulkan hanya data yang diperlukan. NIM, email, nomor pribadi, `passwordHash`, bukti prestasi, avatar mahasiswa, dan audit bersifat privat. Respons tim & undangan hanya menyertakan data profil minimal tanpa `passwordHash`, `email`, `nim`, atau `phone`. Ranking mempublikasikan nama tampilan, prodi (sesuai kebijakan), dan poin sesuai keputusan pemilik produk; tujuan serta aktivitas publikasi diberitahukan jelas saat mendaftar, dan dasar pemrosesan serta mekanisme hak subjek ditinjau sebelum pilot nyata (`O-02`). Rujukan resmi: UU No. 27 Tahun 2022, Pasal 16 dan 20 (https://peraturan.bpk.go.id/Details/229798/uu-no-27-tahun-2022). Retensi, penghapusan, koreksi, dan akses data perlu disahkan kampus (`O-03`).

## Upload dan storage
RustFS bucket privat, service account dengan izin minimum, object key acak, tanpa fallback diam-diam ke filesystem lokal `.storage/` pada `NODE_ENV=production`.
- **Bukti prestasi**: 1–3 berkas aktif, ukuran nyata buffer maksimal **8 MB** per berkas, tipe PDF/JPEG/PNG tervalidasi ekstensi + MIME + magic byte, upload/unduh melalui API terotorisasi, pembersihan otomatis objek yatim bila transaksi gagal.
- **Avatar mahasiswa (`K-20`)**: diunggah via multipart ke RustFS (bukan Base64 ke MySQL), ukuran maksimal **2 MB**, tipe JPEG/PNG/WebP tervalidasi magic byte, diakses melalui endpoint stream terotorisasi, dan tidak ditampilkan pada halaman ranking publik.
Scanning malware dan sanitasi metadata gambar menjadi gate produksi sesuai risiko deployment (`O-06`). Jangan memakai kredensial root RustFS dan jangan cache berkas sensitif secara publik.

## API dan web
Validasi skema & enum input/output ketat di backend; CORS pada `NODE_ENV=production` **hanya** mengizinkan `PUBLIC_ORIGIN` (tidak mengizinkan `localhost`). Build produksi frontend wajib fail-safe ke mode `PRODUCTION` tanpa adapter mock, tanpa kartu login instan berkredensial hardcoded, dan tanpa preset berkas PDF palsu. Header keamanan, CSP sesuai aset, proteksi XSS, sanitasi URL sumber/WA, proteksi formula injection CSV, query terparameter melalui Prisma, pagination, batas body, timeout, dan error tanpa stack/rahasia. Log terstruktur dengan `requestId` dan redaksi PII. Jangan pernah menyimpan hostname privat atau password konkret di `.env.example` maupun repo publik. Dependency scan dan image scan menjadi gate CI.

## Keandalan
Health endpoint liveness dan readiness; readiness mengecek ketergantungan kritis. Backup MySQL dan RustFS terjadwal, terenkripsi, dipisah dari host utama bila memungkinkan; restore diuji. Migrasi database hanya satu proses dan dibuat kompatibel dengan rollback aplikasi atau forward fix. Observabilitas minimum: uptime, error rate, latensi, koneksi DB/storage, ruang disk, umur backup, dan antrean verifikasi. RTO/RPO numerik menunggu keputusan operasional.

## Performa dan aksesibilitas
Target awal uji staging: halaman publik interaktif pada jaringan seluler wajar, API daftar dengan pagination stabil pada data pilot, dan unggah 8 MB tanpa timeout. Ambang numerik final ditetapkan dari baseline pengukuran, bukan klaim. UI diuji pada mobile dan keyboard sesuai docs/11.

## Kriteria rilis
Tidak ada rahasia di repo/image; HTTPS tersedia; uji otorisasi lulus; backup/restore dan rollback teruji; kebijakan privasi/publikasi disahkan; data mock tidak masuk produksi; daftar temuan keamanan kritis ditutup.
