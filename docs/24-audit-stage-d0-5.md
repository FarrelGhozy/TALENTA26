# 24 — Audit kode dan UI Stage D0–5

Tanggal: 21 November 2026. Audit membaca dokumen keputusan, PRD, rencana uji, bukti stage, rute, komponen UI, adapter API dan bagian backend yang berkaitan dengan temuan di bawah. Ini tinjauan berbasis kode dan dokumen, bukan pengujian menyeluruh setiap cabang atau sertifikasi keamanan/aksesibilitas. Tidak ada kode aplikasi yang diubah. Prioritas menunjukkan urutan penanganan yang disarankan, bukan keputusan produk baru.

## Temuan dan tindak lanjut

| ID | Stage | Prioritas | Bukti, dampak, dan penerimaan perbaikan |
|---|---|---|---|
| A-01 | D0 | Tinggi | `README.md` masih menyatakan backend dan infra hanya placeholder dan repo baru Stage 1, sedangkan kode serta TODO mencatat Stage 2–5. `docs/README.md` juga belum mengindeks bukti Stage 5. Rekonsiliasi status aktual, batas yang belum teruji, dan indeks dokumen setelah temuan ini ditriase; jangan menyamakan keberadaan kode dengan kesiapan produksi. |
| A-02 | 1 | Tinggi | `frontend/src/features/ranking/RankingPage.tsx` menyebut ranking dan poin “resmi” serta menyatakan kesesuaian dengan kebijakan kampus, padahal dasar publikasi dan bobot final masih terbuka pada O-01/O-02 di `docs/14`. Teks serupa yang menyiratkan afiliasi/kebijakan perlu diaudit, termasuk footer dan halaman login. Ganti klaim hanya setelah disesuaikan dengan keputusan pemilik; minta keputusan kampus untuk publikasi sebelum data nyata. |
| A-03 | 1, 5 | Sedang | `frontend/src/components/ui/Modal.tsx` memindahkan fokus awal dan mendukung Escape, tetapi tidak mengurung fokus atau mengembalikan fokus ke pemicu; tombol tutup minimum 36px. `Tabs.tsx` menyatakan `aria-controls` tanpa panel yang terkait di halaman ranking dan tidak menyediakan navigasi panah. Perbaiki pola dialog/tab, target sentuh, lalu uji keyboard, pembaca layar, zoom dan viewport kecil; klaim WCAG AA menyeluruh di bukti Stage 5 belum dibuktikan oleh tinjauan ini. |
| A-04 | 1, 3, 5 | Sedang | Banyak label tahun/periode tertanam, misalnya `CompetitionListPage.tsx`, `BerandaPage.tsx`, `AdminDashboardPage.tsx`, `PreparationPage.tsx`, dan default tahun `SuperAdminDashboardPage.tsx`. `frontend/src/lib/format.ts` menggunakan zona waktu browser tanpa `Asia/Jakarta`; adapter API juga mengisi `angkatan: 2026` (`frontend/src/services/api/index.ts`). Gunakan data periode/tahun aktual dan aturan zona waktu, hindari mengarang angkatan; uji pergantian tahun dan browser zona waktu lain. |
| A-05 | 2 | Kritis | `backend/src/lib/mailer.ts` pada cabang SMTP hanya menulis log dan mengembalikan sukses, tanpa mengirim pesan; tanpa SMTP ia mencatat alamat, link dan token reset bahkan pada production. Pengguna tidak dapat mengandalkan pemulihan akun dan log dapat memuat token. Implementasikan pengiriman dan penanganan kegagalan yang nyata, larang fallback token di log produksi, tentukan penyedia sesuai O-04, dan uji pengiriman serta redaksi log. |
| A-06 | 2 | Tinggi | `frontend/src/services/api/index.ts` menyimpan bearer token sesi di localStorage walaupun backend juga memasang cookie HttpOnly. Token dapat diakses JavaScript dan memperbesar dampak XSS; `backend/src/modules/auth/index.ts` mempercayai `x-forwarded-for` mentah untuk pembatasan, dengan fallback IP yang sama. Tetapkan satu strategi sesi dan CSRF, konfigurasi proxy tepercaya serta rate limit yang sesuai deployment; uji spoofing header, sesi dan beberapa instance. |
| A-07 | 3 | Tinggi | Rute frontend di `frontend/src/app/router.tsx` untuk validator hanya dashboard dan prestasi; tidak ada layar pengelolaan kompetisi, jadwal, roadmap, kontak atau seleksi sebagaimana J3. `frontend/src/services/api/index.ts` memiliki `save` ke `/competitions`, sedangkan rute administrasi ada di `/admin/competitions`. Ketersediaan endpoint bukan bukti validator dapat menjalankan J3. Bangun dan uji alur CRUD/publikasi yang disetujui serta selaraskan kontrak; identifikasi cakupan seleksi yang benar-benar tersedia. |
| A-08 | 4 | Tinggi | `backend/src/modules/achievements/service.ts` memvalidasi ukuran, ekstensi dan MIME yang dikirim, tetapi tidak memeriksa isi/signature berkas; unggahan dilakukan di dalam transaksi DB tanpa kompensasi bila unggahan berikutnya atau transaksi gagal. Berkas palsu dapat lolos validasi metadata dan objek yatim dapat tertinggal. Uji signature, batas dan kegagalan storage/DB; tambahkan pembersihan yang terjamin dan putuskan pemeriksaan malware sesuai O-06. |
| A-09 | 4 | Tinggi | `getPublicRanking` di `backend/src/modules/achievements/service.ts` membiarkan filter ledger kosong jika periode aktif tidak ada, sehingga seluruh periode dapat dihitung pada tab periode berjalan. Pengajuan tanpa periode aktif juga dapat disimpan dengan periode null. Tentukan perilaku gagal/kosong tanpa periode aktif, pertahankan riwayat dan uji transisi periode serta periode kosong sebelum memakai ranking nyata. |
| A-10 | 5 | Tinggi | `escapeCsvField` di `backend/src/modules/dashboard/service.ts` hanya mengutip dan menggandakan tanda kutip; teks masukan mahasiswa yang diawali `=`, `+`, `-` atau `@` dapat diproses sebagai formula oleh aplikasi spreadsheet. Terapkan mitigasi formula injection untuk semua kolom teks dan uji nilai berbahaya saat dibuka pada aplikasi spreadsheet yang didukung. |
| A-11 | 5 | Tinggi | `docs/23-validasi-stage-5.md` menyatakan semua kriteria dan WCAG AA lulus, sedangkan `docs/18` juga mensyaratkan uji E2E J1–J5, CSRF, upload berbahaya, performa, retensi dan operasi; dokumen bukti tidak memberikan hasil terperinci untuk semuanya, dan A-03/A-07/A-08 menunjukkan celah. Audit bukti tiap kriteria dan koreksi status gate bersama pemilik; jangan mengandalkan klaim penutupan sebagai persetujuan go-live. Backup DB yang dicatat tidak membuktikan backup/restore objek RustFS. |

## Verifikasi audit dan batasannya

- `bun run typecheck`, `bun run lint`, dan `bun run build` lulus pada 21 November 2026.
- Tidak menjalankan suite integrasi yang membutuhkan MySQL/RustFS atau restore karena dapat mengubah layanan/data; hasil 86 tes pada dokumen terdahulu tidak diverifikasi ulang.
- UI dinilai melalui rute, komponen, teks dan state dalam kode; tidak ada pemeriksaan visual baru di browser, uji responsif, keyboard, pembaca layar, kontras, atau pengujian pengguna pada audit ini. Temuan UI bukan daftar lengkap masalah visual.
- Temuan adalah usulan perbaikan dan area pembuktian, bukan pengesahan perubahan aturan bisnis. Keputusan O-01–O-06 tetap mengikuti `docs/14`.
